# 社媒分享：规则拆解与发布方案

## 一、GitHub 仓库能不能当「社媒分享链接」？

**结论：不建议。** 它可以当第 6 项的**体验链接**（走 GitHub Pages），但第 8 项别用它。

对照规则里的四个有效条件：

| 条件 | GitHub 仓库 | 判断 |
| --- | --- | --- |
| ① 分享内容包含本活动或参赛作品信息 | README 里写了，算 | ✅ 勉强 |
| ② 内容公开可见 | public repo 满足 | ✅ |
| ③ 链接活动期内正常打开 | 满足 | ✅ |
| ④ 带上 `#WorkBuddy #1024程序员节` | 得塞进 README | ⚠️ 形式上满足，但不像「分享内容」 |

真正的问题不在前三条，而在**人气分怎么算**：规则写的是「该链接公开可见的**点赞数与收藏数之和**」。GitHub 有 star，没有「收藏」；审核的人要不要把 star 折算成点赞？没有依据。**大概率按 0 人气计**，你只能拿到 10 分基础分，20 分的人气分直接归零。

而且「社交媒体」这个词，评审大概率按小红书 / 微博 / 知乎 / 掘金这类内容平台理解，不会按代码托管平台理解。

**所以：GitHub 负责「能用」，社媒负责「被看见」，两件事分开做。**

---

## 二、这 30 分到底怎么拿

```
社媒加分 = 10（基础，审核通过即有）+ 人气分（按点赞+收藏）
```

| 点赞 + 收藏 | 人气分 | 合计 |
| --- | --- | --- |
| 10 – 30 | +5 | 15 |
| 31 – 60 | +10 | 20 |
| 61 – 100 | +15 | 25 |
| 101 及以上 | +20 | 30 |

**关键数字是 10。** 少于 10 个赞藏，人气分一分没有。所以目标不是「爆款」，而是「**稳稳过 10，尽量摸 31**」。31 个赞藏对程序员内容不算难——一个 500 人的群转发一次就够。

**时间**：11 月 2 日统一核验。今天 10 月 23 日，还有 10 天。**10 月 24 日就是 1024 程序员节**，那是全年最好的发布窗口。

## 三、平台排序

1. **小红书（首选）**
   平台原生，「收藏」是它的核心动作，正好对上规则的计分口径；小工具也能直接嵌在笔记里。如果第 6 项填的就是这条笔记链接，两处可以填同一个（规则明确允许）。

2. **即刻 / V2EX / 掘金（补充）**
   程序员密度高，容易起量。但注意：**第 8 项只能填一个链接**，选数据最好的那个。

3. **微博（备选）**
   带话题标签最自然，但冷启动难。

4. **GitHub（只做体验链接）**
   别指望它贡献社媒分。

## 七、还能怎么放大

规则只要求「一条公开笔记」，但分数按赞藏算。下面这些不违规，只是把一条笔记的效果做大：

1. **发在 10 月 24 日当天。** 1024 是程序员节，全天信息流都在聊程序员，你的内容天然有语境。拖到月底，热度就散了。

2. **评论区自己先铺一条。** 正文结尾问了「你的第一个 bug 是什么」，发出去后立刻用自己的号回一条真实经历（越具体越好：什么项目、什么现象、怎么发现的）。有第一条才有第二条。

3. **把「世界厅」拆成系列。** 主线笔记发完，隔天单发「世界厅 · Log4Shell」「世界厅 · 阿丽亚娜 5 号」，一条讲一个故事，结尾都指向主贴。内容你已经有了，这是最省力的二次分发。

4. **蹭 php2shell 的正确姿势。** 不要写成漏洞分析（会违规，也没人看），写成「这件事让我想起了什么」。热点只是入场券，落点还得是作品。

5. **不要写成产品介绍。** 小红书最忌讳功能清单。「19 种形制、支持导出、双语切换」这种句式放 README 里。正文只讲一件事：**你为什么做它**。

6. **标题带数字比不带好。** 「27 件真事」「十年代码」「一座博物馆」，数字给的是确定性。

## 八、发布注意

- **笔记必须公开**，不能设「仅自己可见」，不能删，活动期内要能打开。
- 小红书正文不能放外链，链接放在**评论区置顶**或**个人简介**，正文写「链接在评论区」。
- 发完把笔记链接复制下来，填到第 8 项。
- 11 月 2 日前**别改标题、别删笔记**——主办方要按当时的快照核验。
- 话题 `#WorkBuddy` `#1024程序员节` 是**硬性要求**，少了这条分享无效。

---

## 九、如果你还是想用 GitHub

可以，但请同时满足：

1. 仓库是 **public**；
2. README **顶部**（不是文末）放上活动信息与话题；
3. 同时在至少一个小红书/微博帖子发同样内容，第 8 项填那个帖子。

README 顶部可以插这一段：

```markdown
> 参赛作品 · WorkBuddy #1024程序员节
> 一个把 bug 当文物收藏的博物馆。#WorkBuddy #1024程序员节
```

但即便这样，人气分仍是 0——**只解决「有效」，不解决「得分」**。

---

## 十、一句话总结

**GitHub 用来装作品，小红书用来换分数。** 10 天时间，发一篇笔记，凑够 31 个赞藏，拿 20 分；剩下的精力放回作品本身。
