# 社媒分享：规则拆解与发布方案

## 一、GitHub 仓库能不能当「社媒分享链接」？

**结论：不建议。** 它可以当第 6 项的**体验链接**（走 GitHub Pages），但第 8 项别用它。

对照规则里的四个有效条件：

| 条件 | GitHub 仓库 | 判断 |
|---|---|---|
| ① 分享内容包含本活动或参赛作品信息 | README 里写了，算 | ✅ 勉强 |
| ② 内容公开可见 | public repo 满足 | ✅ |
| ③ 链接活动期内正常打开 | 满足 | ✅ |
| ④ 带上 `#WorkBuddy #1024程序员节` | 得塞进 README | ⚠️ 形式上满足，但不像「分享内容」 |

真正的问题不在前三条，而在**人气分怎么算**：规则写的是「该链接公开可见的**点赞数与收藏数之和**」。GitHub 有 star，没有「收藏」；审核的人要不要把 star 折算成点赞？没有依据。**大概率按 0 人气计**，你只能拿到 10 分基础分，20 分的人气分直接归零。

而且「社交媒体」这个词，评审大概率按小红书 / 微博 / 知乎 / 掘金这类内容平台理解，不会按代码托管平台理解。

**所以：GitHub 负责「能用」，社媒负责「被看见」，两件事分开做。**

---

## 二、这 30 分到底怎么拿

```
社媒加分 = 10（基础，审核通过即有）+ 人气分（按点赞+收藏）
```

| 点赞 + 收藏 | 人气分 | 合计 |
|---|---|---|
| 10 – 30 | +5 | 15 |
| 31 – 60 | +10 | 20 |
| 61 – 100 | +15 | 25 |
| 101 及以上 | +20 | 30 |

**关键数字是 10。** 少于 10 个赞藏，人气分一分没有。所以目标不是「爆款」，而是「**稳稳过 10，尽量摸 31**」。31 个赞藏对程序员内容不算难——一个 500 人的群转发一次就够。

**时间**：11 月 2 日统一核验。今天是 10 月 23 日，还有 10 天，节奏完全够。但别拖到 10 月 31 日发——冷启动需要时间。

## 三、平台排序

1. **小红书（首选）**
   平台原生，「收藏」是它的核心动作，正好对上规则的计分口径；小工具也能直接嵌在笔记里。如果第 6 项填的就是这条笔记链接，两处可以填同一个（规则明确允许）。

2. **即刻 / V2EX / 掘金（补充）**
   程序员密度高，容易起量。但注意：**第 8 项只能填一个链接**，选数据最好的那个，别分散。

3. **微博（备选）**
   带话题标签最自然，但冷启动难。

4. **GitHub（只做体验链接）**
   别指望它贡献社媒分。

## 四、小红书发布方案

### 标题（≤20 字，平台限制）

> 我把修过的 bug 做成了博物馆

备选：
- 写了十年代码，最舍不得删的是 bug
- 给每个 bug 写一张展签，然后挂起来

### 正文

```
写了十年代码，最舍不得删的其实是那些 bug。

凌晨三点的空指针、差八小时的时区、
清不掉的缓存、重启就自己好的玄学……

修完的那一刻如释重负，然后它们就被删掉了，
连个名字都没留下。

所以我做了一个地方收着它们：

给它起名、选形制、填一句死因，
系统会自动断代、写一段展签，
再生成一件几何文物，摆进展柜。

🔸 能导出成 1000×1400 的展签图
🔸 挑六件还能生成一张策展海报
🔸 世界厅收了 27 件真事：Log4Shell、心脏出血、
   阿丽亚娜 5 号、一条命令删掉 S3……覆盖 9 种语言，
   可以借进自己的馆里，和你的 bug 并排挂

不用注册，不联网，数据只存在你自己的浏览器里。
中英双语，还有一套「日展」的白色皮肤。

你的第一个 bug 是什么？

#WorkBuddy #1024程序员节 #程序员 #独立开发 #前端开发
```

> 话题里 `#WorkBuddy` `#1024程序员节` 是**硬性要求**，少了这条分享无效。其余标签随意，帮助分发。

### 配图（9 张，3:4 封面打头）

| 顺序 | 文件 | 说明 |
|---|---|---|
| 1 | `social/cover-3x4.png` | **封面**，1080×1440，大字标题 |

| 3 | `screenshots/03-world.png` | 世界厅，说明「有多少」 |
| 4 | `screenshots/06-poster.png` | 策展海报，说明「能出图」 |
| 5 | `screenshots/07-card.png` | 展签图，同上 |
| 6 | `screenshots/04-day.png` | 日展，制造反差 |
| 7 | `screenshots/05-curate.png` | 策展面板 |
| 8 | `screenshots/08-mobile.png` | 手机端 |
| 9 | `screenshots/09-en.png` | 英文版 |

第 1 张决定点击率，别用纯截图，用做好的封面。

### 发布注意

- **笔记必须公开**，不能设「仅自己可见」，不能删，活动期内要能打开。
- 小红书正文不能放外链，链接放在**评论区置顶**或**个人简介**，正文写「链接在评论区」。
- 发完把笔记链接复制下来，填到第 8 项。
- 11 月 2 日前别改标题、别删笔记。

## 五、如果你还是想用 GitHub

可以，但请同时满足：

1. 仓库是 **public**；
2. README **顶部**（不是文末）放上活动信息与话题；
3. 同时在至少一个小红书/微博帖子发同样内容，第 8 项填那个帖子。

README 顶部可以插这一段：

```markdown
> 参赛作品 · WorkBuddy #1024程序员节
> 一个把 bug 当文物收藏的博物馆。#WorkBuddy #1024程序员节
```

但即便这样，人气分仍是 0——**只解决「有效」，不解决「得分」**。

## 六、一句话总结

**GitHub 用来装作品，小红书用来换分数。** 10 天时间，发一篇笔记，凑够 31 个赞藏，拿 20 分；剩下的精力放回作品本身。
